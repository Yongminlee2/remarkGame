# 끝말잇기 (WordChain)

> **Made by LYM** · 문의 dydals5678@gmail.com
> 저장소 <https://github.com/Yongminlee2/remarkGame> · 현재 버전 **1.3.2 (빌드 3)**

AI와 1:1로 대결하는 한국어 끝말잇기 안드로이드 게임. 채팅하듯 말풍선으로 주고받는 UI에,
표준국어대사전+끄투 DB 기반 **43만 단어 사전**과 **뜻풀이 43만 건**을 완전 오프라인으로 내장했다.

한 판 하고 끝나는 게임이 아니라 **다시 켤 이유**를 만드는 데 집중했다.
무한 스테이지와 보스로 이어지는 모험 모드, 레벨·랭크, 아바타 48종 도감, 일일 미션과 연속 출석이
서로 맞물려 하나의 순환 고리를 이룬다.

기획→디자인→데이터 수집·가공→코딩→효과음/BGM 합성→실기기 테스트까지 전 과정을 직접 진행한 개인 프로젝트다.

| 기능 | 설명 |

| 제한시간 분리 | 난이도와 별개로 "제한시간 없이 느긋하게" 스위치 (무제한 × 어려움 조합 가능) |
| 두음법칙 | 력→역, 라→나, 뉴→유 등 자동 인정 (초성 ㄹ/ㄴ 완화 규칙을 유니코드 분해로 계산) |
| 한방단어 | 어려움만 6라운드 이후 사용, 매우쉬움~보통은 **절대 금지** (시뮬레이션으로 검증) |
| 단어 뜻풀이 | AI든 나든 단어를 내면 말풍선 안에 사전 뜻이 작게 표시. **43만 단어 전부 뜻이 뜬다** |

## 빌드

```bash
# Windows, JDK 17+ (gradle.properties에 Android Studio JBR 경로 지정돼 있음)
gradlew.bat :app:assembleDebug
# → app/build/outputs/apk/debug/app-debug.apk
```

단위 테스트 94개:

```bash
gradlew.bat :app:testDebugUnitTest
```

> **한글 사용자 경로 주의.** 홈 경로에 한글이 들어간 환경(예: `C:\Users\사용자`)에서는
> Gradle 테스트 워커가 클래스패스를 못 읽고 `ClassNotFoundException: ...GradleWorkerMain`으로 죽는다.
> 이때는 Gradle 홈을 ASCII 경로로 지정해 실행한다:
> `GRADLE_USER_HOME=C:/gradle-home gradlew.bat :app:testDebugUnitTest`
> (빌드는 이 변수 없이도 된다.) 결과는 `BUILD SUCCESSFUL`이 아니라
> `app/build/test-results/testDebugUnitTest/*.xml`의 `tests=`/`failures=`로 확인할 것.

밸런스 하네스(앱 빌드와 무관, 단일 파일 실행):

```bash
java -Dstdout.encoding=UTF-8 tools/BalanceSim.java
```

### 설계 포인트

- **동음이의어 고르기**: 처음 쓰던 데이터셋은 표제어당 뜻이 **하나뿐**이었고 하필 희귀한 쪽을
  골라 뒀다 — '사과'가 沙果도 謝過도 아닌 赦過(잘못을 용서함), '관리'가 管理가 아닌 菅履(엄짚신).
  국립국어원이 배포하는 표준국어대사전 XML에는 동음이의어가 `<item>`으로 전부 들어 있어
  **그중 실제로 흔한 뜻을 고를 수 있다.** 빈도 수치는 없으므로 사전이 남긴 흔적으로 가늠했다 —
  용례가 몇 개 달렸는가, 방언·옛말·북한어는 아닌가, 전문 분야 용어뿐인가, 뜻이 여러 갈래인가.
  흔히 쓰는 말일수록 용례가 붙고 뜻이 갈라진다는 성질을 점수로 옮겼다.
  용례 자체는 문학작품·기사 인용이 섞여 저작권이 따로 걸리므로 **개수만 세고 본문에는 싣지 않는다.**
- **뜻풀이 빈칸 메우기**: 그러고도 파생어·합성어는 뜻이 비는 일이 잦다.
  '가가대소'는 있는데 '가가대소하다'가 없는 식이다. 소스 두 개를 우선순위로 합쳐
  **실제 사전 뜻 96.2%**를 확보하고, 남은 3.8%는 규칙으로 채웠다 —
  접미사를 떼어 어근 뜻을 살리고(-하다/-되다/-거리다/-히 …), 합성어는 양쪽으로 갈라 잇고,
  어근을 못 찾으면 끄투 낱말표의 품사·분야 꼬리표로 "부사." "《화학》 분야의 명사."까지 후퇴한다.
  **없는 뜻을 지어내지 않는 것이 원칙**이라, 끝까지 모르는 것은 모른다고 밝힌다.
  자동 생성분은 정보 화면에 그렇게 만들었다고 표시한다.
  뜻풀이 자산 세 파일은 서로를 전제해서 하나만 다시 만들면 모든 단어가 엉뚱한 뜻을 달게 되는데
  화면에서는 "이상한 뜻"으로만 보여 알아채기 어렵다. 그래서 자산 정합성을 단위 테스트로 묶었다.
- **사전 자료구조**: 43만 단어를 HashSet 대신 **정렬 String 배열 + 이진탐색**으로 보관.
  단어 검증 O(log n), 첫 글자 범위 조회(lower bound)로 AI 후보 탐색. 뜻풀이는 메모리에 올리지 않고
  `means.idx` 오프셋으로 필요할 때만 파일에서 읽는다(첫 실행 시 filesDir로 복사 후 RandomAccessFile).
- **AI 전략**(GameEngine.pickAiWord):
  - 매우쉬움: 상용 단어 중 플레이어가 잇기 좋은 것만(followUp≥8), 한방단어 금지, 5라운드부터 항복 확률
  - 쉬움: 상용 단어, followUp≥5, 8라운드부터 항복 확률
  - 보통: 상용 단어 위주 무작위, 부족하면 전체 사전에서 짧은 단어
  - 어려움: 전체 사전에서 플레이어 후보를 최소화하는 단어, 6라운드부터 한방단어 허용
- **BGM 합성**: 5가지 스타일(패드/플럭/오르골/마림바/베이스그루브) × 7가지 코드진행 × 조성 ±6 × 템포 70~109를
  시드 고정 난수로 조합해 20곡 생성, libvorbis q2로 전곡 1.6MB.
- **밸런스 검증**: 데스크톱 시뮬레이션(무작위 유효단어 플레이어 × 난이도별 150판)으로
  "AI 규칙위반 0건 / 매우쉬움~보통 한방단어 0건"을 확인하고 출시.
- **화면과 로직 분리**: 난이도 곡선·보스 규칙·아바타 카탈로그·미션·보상 계산을 전부 Android 의존 없는
  순수 Kotlin으로 뺐다. 덕분에 위험한 부분(레벨 곡선, 두음법칙, 마이그레이션)을 단위 테스트 94개로 잡을 수 있고,
  화면은 그 결과를 그리기만 한다.
- **보스 규칙은 두 곳에 동시 적용**: 플레이어 단어 검증뿐 아니라 **한방단어 판정과 AI 후보 탐색에도**
  같은 규칙을 건다. 한쪽만 걸면 "받침 있는 단어만" 같은 규칙에서 후보가 전멸했을 때
  플레이어가 아무 잘못 없이 지는 버그가 난다. 규칙 통과 후보가 0개면 AI 항복(플레이어 승리)으로 처리한다.
- **조합형 아바타**: 몸통 1장 + 눈썹 2장 + 눈 2장 + 입 1장을 겹쳐 그린다.
  눈·눈썹 에셋은 "한 짝"짜리라 좌우로 두 번 그리고, 오른쪽은 좌우 반전해 대칭을 만든다.
  Kenney 파츠는 타이트하게 크롭돼 있어(몸통 80×80, 눈 20×20, 입 20×7) 그냥 겹치면 얼굴이 몸을 덮는다.
  측정된 뷰 크기 기준으로 눈썹은 상단 0.24, 눈은 폭 0.16·상단 0.34, 입은 폭 0.24·상단 0.60에 배치하고
  높이는 각 PNG의 고유 종횡비에서 역산한다. 표정 8종을 48개 아바타에 6개씩 고르게 뿌린다.
- **스테이지 규칙 배정**: 규칙 종류가 적어 스테이지마다 독립 추첨하면 같은 규칙이 세 판 연속 나온다.
  풀 순서를 한 번 고정해두고 스테이지 번호로 그 안을 순회해 인접 스테이지가 절대 겹치지 않게 했다.
  보스는 **단어 제약 1개 + 압박 규칙 1개**로 고정 — 단어 제약끼리 섞으면
  "두 글자만 + 3글자 이상"처럼 통과 단어가 0개인 조합이 나온다.
- **이어가기 방식은 단어 제약과 다른 축**: "앞 글자로 끝내기"는 사전을 뒤에서 찾는 규칙이라
  "네 글자만" 같은 제약과 겹치면 난이도가 곱해진다. 그래서 한 스테이지에는 둘 중 하나만 건다.
  앞말잇기는 **끝 글자 역색인**이 따로 필요해 첫 조회 때 43만 단어를 한 번 훑는다 —
  박싱 없이 두 번 세는 방식(개수 집계 → IntArray 채우기)으로 만들고,
  사전 로딩이 끝난 시점에 백그라운드로 미리 준비시켜 입력 중 멈춤을 없앴다.
  전수 측정(`ChainSafetySim`) 결과 다음 차례가 막히는 비율은
  끝말잇기 0.40% / 같은 글자 0.00% / 앞말잇기 1.40%로, AI의 후속 단어 계산도 방식별로 갈아끼워
  낮은 난이도에서 플레이어에게 막다른 단어를 넘기지 않게 했다.

8. **v1.3.2 — 동음이의어 교정 · 조작 다듬기**
   - **문제 제기**: "사과를 냈는데 뜻이 '잘못을 용서함'이라고 뜬다."
     확인해 보니 사과만이 아니었다 — 관리=菅履(엄짚신), 가계=家鷄(집닭),
     만화=萬貨, 기사=騎射, 연기=連記. 흔한 말일수록 엉뚱한 한자가 붙어 있었다.
   - **원인**: 쓰던 데이터셋이 표제어당 뜻을 **하나만** 담고 있었고, 그 하나를 고르는
     기준이 없었다. 파서를 아무리 고쳐도 없는 뜻은 못 만든다 — 소스를 바꿔야 했다.
   - **해결**: 국립국어원이 stdict.korean.go.kr 로 배포하는 표준국어대사전 XML
     (43만 항목, 87개 파일, CC BY-SA 2.0 KR)로 갈아탐. 여기엔 동음이의어가
     `<item>` 으로 전부 들어 있어 **고를 수 있다**는 게 핵심이다.
   - **고르는 법**: 사전에 빈도 수치는 없다. 대신 사전이 남긴 흔적으로 가늠했다 —
     용례가 몇 개 붙었는가(흔히 쓰는 말일수록 예문이 달린다), 방언·옛말·북한어는
     아닌가, 전문 분야 용어뿐인가, 뜻이 여러 갈래로 갈리는가. 이걸 점수로 옮겨
     동음이의어 중 최고점을 뽑는다.
   - **저작권**: 용례에는 문학작품·기사에서 따온 것이 섞여 있어 사전 본문과
     저작권이 따로 논다. 그래서 **개수만 세고 본문에는 싣지 않는다.**
     기존 데이터에 박혀 있던 `❖예문 …` 도 이번에 전부 걷어냈다.
   - **결과**: 실제 사전 뜻 82% → **96.2%**, 규칙 생성분 18% → **3.8%**.
     4단 파이프라인으로 정리(`extract_stdict` → `extract_kkutu_meta` →
     `build_means` → `gen_means`)해 언제든 다시 만들 수 있게 함
   - **항복 시 부활 안 묻기**: 항복은 스스로 그만두는 것인데 부활을 권하고 있었다.
     종료 사유를 문자열로 판별하던 것을 명시적 인자(`canRevive`)로 바꿔
     '져서 끝났을 때'와 '스스로 그만둔 때'를 갈랐다
   - **스테이지 조건 키우기**: "무슨 조건인지 눈에 안 들어온다"는 지적을 반영해
     모험 화면 조건 글씨를 14sp → **19sp**, 배경 판과 색 테두리 추가
     (보스는 빨강, 일반은 노랑). 게임 화면 배너와 같은 모양으로 맞춤
   - 실기기(갤럭시 S20 Ultra)에서 설치·확인: 조건 배너 가독성, 새 뜻풀이
     (고등학교 → 高等學校 …), 항복 시 부활 미표시까지 눈으로 검증

진짜 원인은 조합 수 부족이라 연속일 중복 방지 로직으로 고쳤다.

### v1.3.1~1.3.2에서 잡은 것

| 심각도 | 문제 | 원인 |
|---|---|---|
| High | 흔한 단어에 엉뚱한 뜻 | 소스 데이터셋이 표제어당 뜻을 하나만 담았고 희귀 동음이의어를 골라 둠 — 파서가 아니라 **소스의 한계**였다 |
| Medium | 파생어 18%가 뜻 없음 | 원본 사전에 '가가대소'는 있어도 '가가대소하다'는 없음 |
| Medium | 항복해도 부활을 물음 | 종료 사유를 문자열(`reason`)로 판별해 '스스로 그만둠'과 '져서 끝남'을 구분 못 함 |
| Low | 스테이지 조건이 안 보임 | 본문과 같은 14sp 로 조용히 놓여 있어 처음 보면 못 알아챔 |
| Low | 잘린 뜻풀이가 상한 초과 | 160바이트로 자른 뒤 말줄임표(3B)를 덧붙여 실제로는 163바이트 |

**교훈 — 어디를 고쳐야 하는지부터 확인할 것.** 뜻이 이상하다는 신고를 받고 처음엔
파서를 의심했다. 소스를 다시 받아 원본 레코드를 직접 열어 보고서야 데이터셋 자체가
표제어당 한 뜻만 담고 있다는 걸 알았다. 확인 없이 파서를 고쳤다면 시간만 버렸을 것이다.
끄투 공개 덤프의 뜻풀이 칸이 전부 자리표로 비어 있다는 것도 같은 방법으로 알아냈다.

**교훈 — 서로를 전제하는 자산은 테스트로 묶을 것.** `dict_all.txt`·`means.bin`·`means.idx`는
i번째 단어의 뜻이 `means.bin[idx[i]..idx[i+1]]` 이라는 약속으로 이어져 있다. 하나만 다시
만들고 나머지를 안 맞추면 **모든 단어가 엉뚱한 뜻을 달게 되는데**, 화면에서는 그냥
"이상한 뜻"으로 보여서 알아채기 어렵다. `MeansAssetTest` 5개로 이 약속을 고정했다.

## 알려진 한계

- **레벨 곡선이 초반에 조금 느리다.** 목표는 레벨 10까지 15판·레벨 20까지 40판이었는데
  실측은 17판·43판이 나왔다(레벨 50은 127판으로 목표 200판 통과). 체감상 크게 답답하진 않아
  일단 두고 있다. 조이려면 `Progress.xpForNextLevel`의 계수 50을 46 근처로 내리면 되고,
  그때 `ProgressTest`의 기대값도 함께 고쳐야 한다.
- **보스 규칙에 따라 AI가 일찍 항복할 수 있다.** 사전 전체를 훑어보면 규칙 통과 단어가 하나도 없는
  시작 글자가 있다(3글자↑ 13.1%, 받침 18.5%, 4글자↑ 23.7%). 다만 단어량 기준으론 0.25% 미만인
  희귀·고어 음절이라 실제로 걸릴 일은 드물고, 걸려도 플레이어 패배가 아니라 AI 항복으로 처리된다.
- **테스트가 순수 로직에 한정된다.** `WordDict`가 Android 에셋에 의존해서 `GameEngine` 자체는
  JVM 단위 테스트로 못 돌린다. 화면과 사전이 얽힌 부분은 실기기 확인에 의존한다.
  (자산 **파일**의 정합성은 `MeansAssetTest`가 안드로이드 없이 직접 읽어 확인한다.)
- **동음이의어 선택이 완벽하진 않다.** 용례 개수로 흔한 뜻을 가늠하는 방식이라,
  둘 다 흔한 경우엔 갈릴 수 있다 — 예컨대 '수도'는 首都가 아니라 水道가 뽑힌다.
  기준을 조이거나 예외 목록을 두면 되지만, 지금은 눈에 띄는 오선택이 거의 없어 두고 있다.
- **뜻풀이 3.8%는 규칙으로 만든 문장이다.** 원본 사전에 아예 없는 파생어·합성어로,
  어근의 실제 뜻에서 조립한 것이라 없는 뜻을 지어내진 않지만 사전 문장은 아니다.
  이 사실은 앱 정보 화면에 밝혀 두었다.
